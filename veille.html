L'intelligence artificielle dans le développement logiciel

Suivre l'évolution des assistants de code et des outils d'IA générative, pour savoir ce qu'ils changent dans le métier de développeur et comment les utiliser sans perdre la maîtrise de son code.

Problématique

Comment l'IA générative transforme-t-elle le travail d'un développeur, et jusqu'où peut-on lui faire confiance ?

Pourquoi ce sujet

Pendant mon stage, j'ai développé des outils en PowerShell (gestion des astreintes IT, clôture de tickets via une API REST, audits Active Directory). L'IA est déjà présente dans ce type de travail : elle aide à écrire, déboguer et documenter du code. Je veux comprendre ce qu'elle apporte vraiment, ses limites, et les risques qu'elle crée pour la sécurité et la confidentialité des données.

Synthèse

1. Les outils deviennent des agents. On passe de l'assistant qui répond à une question à des agents qui planifient, testent et agissent presque seuls. Le développeur devient celui qui cadre et vérifie le travail.

2. Le gain de productivité est réel mais nuancé. Produire plus de code ne veut pas dire livrer plus de valeur, et le coût d'usage devient un vrai sujet de choix.

3. La sécurité est le point faible. Une part importante du code généré contient des failles. L'IA écrit du code qui fonctionne, pas forcément du code sûr.

Pour mes projets : j'utilise l'IA comme aide, mais je relis et teste chaque script avant de l'utiliser, et je n'envoie jamais de données internes (comptes, noms de serveurs, identifiants) à un outil externe.
